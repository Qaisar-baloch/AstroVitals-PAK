# AstroVitals PAK — 3–5 Minute Demo Script

## Before recording or presenting

- Open https://astrovitalspak.netlify.app
- Use the synthetic demonstration crew only.
- Confirm the anatomy model has loaded.
- Avoid entering real personal or medical information.
- If internet access is unreliable, preload the app and anatomy assets before presenting.

## 0:00–0:30 — Introduce the problem

“Long-duration space missions create a challenging health-monitoring environment. Crew members need ways to record how they are doing, review trends, and communicate health-related information clearly. AstroVitals PAK is a prototype exploring how these workflows could be brought together in one interface.”

## 0:30–1:10 — Mission Control

“Mission Control provides a high-level view of four synthetic crew members. It summarizes demonstration status indicators and gives the commander a starting point for opening an individual crew profile. All values in this demo are synthetic.”

Show the four crew cards and open one profile.

## 1:10–2:00 — 3D anatomy explorer

“The anatomy workspace provides an interactive educational 3D reference. I can rotate and zoom the model, switch visible body systems, and select a structure to view related contextual information. The model is for exploration and education, not diagnosis.”

Rotate the model, switch a layer, select a body structure, and show the regional information panel.

## 2:00–2:45 — Check-in and analytics

“A crew member can record a manual self-assessment. These entries are stored locally in this browser. The analytics workspace keeps manually entered check-ins separate from simulated telemetry, so the source of each dataset remains clear.”

Create or open a demo check-in and show the corresponding trend view.

## 2:45–3:30 — Alerts and science context

“The alert workspace organizes demonstration events into information, warning, and critical workflow categories, with acknowledgement history. The science library connects the project to NASA educational resources and maps mission hazards to monitoring topics where the project has supporting context.”

Acknowledge a demo alert and open the NASA science library.

## 3:30–4:00 — Close with limitations

“AstroVitals PAK is a student prototype. It is not a medical device, does not diagnose or recommend treatment, and is not connected to real astronaut sensors. Its purpose is to demonstrate an accessible interface concept for crew self-assessment, health-data organization, and mission awareness.”

## Presentation tips

- Keep the demo focused on one crew member after the overview.
- Do not claim real-time sensor integration.
- Do not describe demo thresholds as medical standards.
- Do not imply NASA endorsement.
- Use the live URL and repository link on the final slide.
